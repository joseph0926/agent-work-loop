1. 루프 한 바퀴

실제 작업에서 생긴 실패와 취향, 활동 기록이 다음 작업에 반영된다. 흐름마다 판단 주체와 사용자가 개입하는 정도가 다르다.

루프의 중심

실제 작업

사람이 요청하고 에이전트가 작업한다. 작업 중 생긴 피드백과 기록이 각 경로로 이어진다. S5 S6 S7

화면 취향은 사용자가 최종 판단한다. 규칙 승격은 에이전트가 검토해 제안하고, 사용자가 승인하면 반영한다.

작업에 적용할 규칙

harness

전역 규칙과 스킬 원본을 관리한다. sync-home으로 배포해 작업에 적용한다. S3 S4

taste와 mirror의 본체와 기록은 tools에 있다. S1 S6 S7

기록을 다음 작업으로 연결하는 흐름

입력작업 중 정정, 되돌림, 범위위반과 반복 실패

실패 inbox S5

기록과 검토: 에이전트 / 요청과 승격 승인: 사용자

  1. 에이전트가 막았을 한 줄과 고칠 곳을 적을 수 있는 실패를 기록
  2. 같은 고칠 곳(owner)에 2건이면 mirror에 승격 검토가 뜸
  3. 사용자가 mirror의 프롬프트를 복사해 에이전트에 검토 요청
  4. 에이전트가 검토해 규칙으로 승격할 항목을 보고
  5. 사용자가 반영을 요청하면 에이전트가 해당 규칙을 수정
반영 대상: 해당 규칙

전역 규칙과 스킬은 harness로, 저장소 전용 규칙은 해당 저장소로 돌아간다.

입력사람의 화면 판정과 시편 비교에서 고른 값

taste S6

최종 판단: 사용자

  1. 사용자가 화면을 평가하고 시편의 값을 선택
  2. 에이전트와 도구가 판정을 기록하고 취향 규칙과 선호로 정리
  3. 훅 등으로 다음 화면 작업에 취향을 전달
반영 대상: 다음 화면 작업

규칙과 고른 값을 적용하고, 사람이 화면을 보며 다시 판단한다.

입력대화 기록과 학습, 구직, 위키, harness의 상태

mirror S7

시작: 사용자 / 판단과 처리: 에이전트

  1. 도구가 기록을 분석해 신호와 할 일을 생성
  2. 사용자가 메뉴바에서 프롬프트를 복사해 에이전트에 요청
  3. 요청받은 에이전트가 내용을 판단하고 처리
  4. 판정 가능한 신호는 도구가 다음 관측에서 해소 확인
반영 대상: 해당 활동

학습, 구직, 규칙 정비 등으로 이어진다. 실패 inbox의 규칙 승격 검토도 mirror의 요청 경로로 시작한다.

↺ 다음 작업에 반영

반영한 결과를 다음 작업과 관측에서 확인한다. 개선 효과는 별도 측정 대상이다. S6 S7

검토와 승인 역할, mirror를 통한 요청과 규칙 승격 절차는 2026-10-16 사용자 설명을 반영했다.

필요할 때 유지, 수정, 은퇴를 결정

사람이 최근 수요와 사용 기록을 보고 규칙, 스킬, 도구를 고치거나 버린다. 세 흐름을 운영하며 필요할 때 내리는 판단이다. S4 S11 S13 S14
